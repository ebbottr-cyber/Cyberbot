# Solana Windows research task (local PC first)

This is an opt-in Windows PowerShell / Task Scheduler package, not a VPS deployment or trading service. Use a dedicated clean Git worktree pinned to the validated commit and an existing Python interpreter. Keep the existing main bot and its databases untouched. The default data directory is `%LOCALAPPDATA%\Cyberbot-Solana-Research`; existing DexTerm archives are not moved or deleted. Do not point it at another application's data directory.

The registration script first runs the isolated offline suite, and additionally runs the native synthetic model check if `-EnableModels` is requested. It creates only a new **disabled** interactive-user task called `Cyberbot-Solana-Research`. No auto-install, administrator elevation, execution-policy bypass, existing-task overwrite or startup is performed. Review the task before explicitly enabling it. The repeat trigger lasts 365 days, with a logon trigger too; each invocation runs one research cycle, and overlapping instances of that task are ignored. No wake-from-sleep is requested. The task cannot collect while the PC is asleep, shut down, or the interactive user is signed out.

Research data rights must be confirmed by the operator. The launcher sets the kill switch in its own process environment only and refuses changed tracked checkout files or an unexpected commit. Any nonzero Python exit or launcher failure inside the execution block creates a persistent stop marker next to the research DB; inspect the logs and review the cause before removing it. A hard termination may leave a stale scheduler lock instead; do not remove that lock until confirming no process is active. The 15-minute task limit is an upper bound, not a guarantee a cycle succeeds.

The task is configured for five-minute trigger intervals, a 24-hour import window and one numerical worker thread where supported. Models are off unless separately enabled. Set the PWA server's `CYBERBOT_SOLANA_PWA_REPORT_DIR` to the dedicated data directory's `reports` subdirectory when integrating the panel. The existing authenticated API remains read-only; the task does not start or expose a server.

No Windows execution has been verified by this commit. Validate the PowerShell scripts and task registration on the intended PC before enabling. The next steps are health reporting, resource/disk monitoring, backup and restore verification, and a bounded real-provider paper-only trial.

## Local resource health preflight

Each Windows launcher invocation now runs a read-only health check and writes a separate local health log before requesting quotes. Defaults: 2 GiB minimum free space on the research volume; 512 MiB minimum available physical RAM; unknown RAM is blocking. A short host CPU sample of 90% or higher is a warning only. These are initial conservative gates, not measured workload requirements or guarantees. A stop or lock marker also blocks preflight; the presence of a lock is not proof of a live process. A stale or invalid PWA publication is reported as a warning, not proof of provider failure. No deletion, process termination, or automatic lock removal occurs. A failed preflight triggers the launcher's persistent halt; manual review is required. The CPU/RAM figures represent the entire Windows host, not Cyberbot process usage. The check can also be run without starting research via `python -m tools.solana_pc_health --data-root <dedicated-directory>`. Actual Windows measurements and threshold tuning remain unverified until PC testing.
